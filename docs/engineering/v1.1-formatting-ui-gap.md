# v1.1 formatting UX: implementation blocker confirmed

Inspected `src/activities/reader/ReaderFormattingActivity.cpp`, `src/activities/reader/QuickOverridesActivity.cpp`, and `src/ReaderFormatting.h`.

## Verified findings
- Per-book `-1` means inherit global, `0` means publisher CSS, and positive values are explicit choices (for fields in `ReaderFormatting`).
- Some explicit zero values are real overrides, e.g. zero first-line indent; NEVER conflate with the original CSS sentinel.
- The formatting menu currently uses 3 visible `STR_BOOK_S_STYLE` entries (alignment, heading alignment, numeric factory); quick overrides has a separate explicit three-state embedded-styles control.
- `ReaderFormattingActivity::row()` always inserts a visible inherited/default entry for book scope.
- Merely renaming the CSS item to `0%` would still be an extra manual mode, not automatic restoration, and would misleadingly conflate varied publisher CSS values.

## Required implementation
1. Introduce a reversible per-property control baseline that removes the override when the user returns to its neutral position; keep publisher CSS as the source of truth.
2. Define the distinct behaviors for local baseline, global inheritance, and publisher CSS. Do not silently reset a book's explicit custom settings during migration.
3. Update numeric, alignment, font and quick override widgets consistently, plus EPUB rendering tests across varied CSS.
4. Do not touch Power wake thresholds or bootloader without confirming timing failure.
5. Build and test in the emulator before any physical X4 Pro test.

## Evidence from this inspection
The locally available working tree still has no v1.1 UI fix. Four available Python structure tests passed on 2026-10-17; these DO NOT demonstrate the new UX or a firmware build. Prior claims of a ready image are not supported.
